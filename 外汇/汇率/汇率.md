## 汇率系统领域

汇率是跨境支付的核心数据，必须自建才能控成本、控风险、控体验。

- 统一多渠道汇率来源，避免不同银行、做市商汇率不一致；
- 控制汇率波动风险，做熔断、监控、异常拦截；汇率波动会直接造成公司亏损。自建系统才能做汇率波动阈值监控、自动熔断、自动刷新、异常汇率拦截。外部渠道不帮你控风险。
- 掌握自主定价权，通过加点形成客户汇率，这是公司重要盈利点；银行 / 渠道只给原始汇率，不能直接给用户用。必须自建系统，在原始汇率上加点（spread），形成商户汇率、用户汇率、渠道汇率这是支付公司最主要的盈利点之一
- 支持锁汇、挂单、套期保值等跨境必需的金融能力；
- 满足高并发、低延迟、高可用的支付要求，并支撑对账、业财、审计全链路。
- 对账、清算、业财一体化汇率是资金、账务、清算的基础数据。必须可追溯、可审计、可回放。外部汇率没有日志、没有回放能力，无法满足合规与业财要求。


### 独立价格源

Mysql配置表

- 行情源配置：src_channel_info、src_channel_mix、src_user  （渠道配置）
- 货币对配置：src_base_symbol、src_std_symbol、src_currency （标准货币对）
- 规则/风控：src_rule_conf、src_table_rule、src_risk_threshold、src_risk_quote_flow
- 人工报价：src_manual_rate、src_manual_rate_his
- 牌价收盘：src_board_close 
- 日历/节假日：eco_calendar_event、src_holiday (日历表)
- 上传和订阅：src_upload、src_client_sub （nio, 向业务系统分发）


#### 多源异构接入
   - 支持 Kafka、RocketMQ、RPC 上传、渠道推送、定时爬虫、手工报价等多种入口。
   - 不同来源的协议、字段、币种代码、精度、报价方向和交易时间不一致，需要分别适配。
       - src_user： 定义有哪些行情源：providerId、code、名称
       - src_channel_info 定义每个源支持哪些 rate_type、symbol、tenor，以及 factor、offset
   - 代码里有 BOC / CEB / CITIC / Eikon / ICBC / Shanghai / WindIB / Yeepay 等来源的转换适配器。
   - 汇率主要存于  Redis + HBase方式
        - Redis中存储 FX:RATE:V3:{rateType}:{symbol}:{providerId}:{tenor} 的汇率，保存15天
        - HBase：历史行情， key键 R:{symbol}:{rateType}:{providerId}:{tenor}:{yyyyMMddHHmmss}
    
#### 套算

本币就是“某个国家、地区或机构自己的货币”，也叫本地货币 / domestic currency。它是相对的，取决于“站在谁的角度”。

> 美元是全球外汇市场的“媒介货币/锚货币/公共计价单位”。因此，许多跨境公司会选用美元做为“本币”

以“美元”为本质为例子

直盘 = 带美元的盘；
  EUR/USD
  USD/JPY
交叉盘 = 不带美元的盘。
  EUR/GBP
  EUR/JPY

套算：说的是“价格怎么算出来”，即通过一个中间货币（通常是 USD）和两个已有汇率推导出目标汇率。 
1 EUR = 1.1000 USD
1 USD = 7.2000 CNY
所以：
1 EUR = 1.1000 × 7.2000 = 7.9200 CNY

##### 套算过程

- 步骤1：定义src_base_symbol —— 基础/直盘货币对
- 步骤2: 定义src_std_symbol 是“系统对外承认的标准货币”， 包括 支持/暂时不支持的
- 步骤3: 确定套算集合ALL ， {src_std_symbol 中支持 -  src_base_symbol - 白名单（行情源直推） } 
     1. 当有新的直盘汇率进来
     2. 算出要当前要套的集合T
        ```
        从 src_base_symbol 中取 SPOT 的 USD 货币对，例如：
           EURUSD   ← 本次进来的，排除
           GBPUSD
           USDCNY
           USDJPY
           USDHKD
           AUDUSD
           ...
        每个 USD 腿和 EURUSD 组合，都会推导出一个目标
           EURUSD + GBPUSD → EURGBP
           EURUSD + USDCNY → EURCNY
           EURUSD + USDJPY → EURJPY
   
         最后和 ALL 相交过滤得到T
        ```
 - 步骤4: src_channel_mix 是合源策略
       ```
           假设：

            
            
            src_channel_mix 中合源配置

            EURUSD:
              providerId  = 0        // 复合源
              bidSrcIds   = [A, B, C]
              askSrcIds   = [A, B, C]
              bidStrategy = AVG
              askStrategy = AVG

            USDCNY:
              providerId  = 0
              bidSrcIds   = [D, E]
              askSrcIds   = [D, E]
              bidStrategy = AVG
              askStrategy = AVG
            
            EURUSD 有 3 个源：A、B、C
            USDCNY 有 2 个源：D、E

            | A | 1.0998 | 1.1000 |
            | B | 1.1000 | 1.1002 |
            | C | 1.1002 | 1.1004 |
            | D | 7.1998 | 7.2002 |
            | E | 7.2000 | 7.2004 |

            EURUSD 复合 Bid = (1.0998 + 1.1000 + 1.1002) / 3 = 1.1000
            EURUSD 复合 Ask = (1.1000 + 1.1002 + 1.1004) / 3 = 1.1002
            USDCNY 复合 Bid = (7.1998 + 7.2000) / 2 = 7.1999
            USDCNY 复合 Ask = (7.2002 + 7.2004) / 2 = 7.2003
   
            可能得到复合 EURUSD：
            
            EURUSD = 7.1999 / 7.2003
        ```
   - 步骤5: 高行情频率的并发策略
        ```
          线程池拒绝策略: 队列满时，丢弃最老的任务，保证新任务能进来。
        ```
